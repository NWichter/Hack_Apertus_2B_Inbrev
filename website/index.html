The practice inbox that never leaves the practice.

Inbrev sorts the incoming mail, HIN mail and faxes of a Swiss general practice with Apertus, built to run on a box inside the practice. Every message gets a handling route, an administrative deadline and a person in charge, and every decision points to the words in the message that support it.

The problem

Practice staff start the day with a mixed pile: lab reports, prescription requests, appointment changes, insurer forms, referrals and advertising, in German, French and Italian.

Read, route, prove

A fixed pipeline, not an agent. Apertus reads free text in four languages; plain code checks everything it says.

  1. Read. E-mail, HIN mail, fax (OCR) and web forms become text. Apertus answers in an enforced JSON schema, three times per message.
  2. Route. One of nine administrative routes, a deadline computed in code from the quoted date, and the person in charge: assistant, doctor or administration.
  3. Prove. Every field needs a verbatim quote that exists in the message. No quote, no value. The inbox highlights the source.

Routes, never triages

Inbrev does not assess clinical content. A message that may contain symptoms is excluded from automation and lands with the messages a person decides, in order of arrival and without any ranking by severity. That keeps the tool administrative.

A person decides when Inbrev is unsure

If the three samples disagree, the model calls a message ambiguous, or no evidence survives the checks, Inbrev does not guess. The message lands in "A person decides".

Status

What is built, what is measured and what is still open. Every number comes from a real run on synthetic, fictional messages whose labels no person has reviewed yet.

Built

  • Pipeline with enforced schema, quote checks, deadline rules and abstention
  • Web inbox with highlighted sources and a JSON API
  • Unit tests and the non-LLM evaluation run in Docker with --network none
  • Taxonomy of nine routes, 12 seed messages written by Claude (not by hand) and a synthetic test set of 180 messages in four languages written by Claude and GPT-5.5, all fictional
  • Measured on the 180 messages: Inbrev with Apertus 8B takes 13 of 16 messages with clinical content out of automation (clinical exclusion recall 0.81, 95 % CI 0.57–0.93) and handles 96 % of all messages without a person; route macro-F1 0.85. Apertus 70B: 15 of 16
  • Baselines without a language model: keyword rules route 79 % correctly but catch only 7 of 16 messages with clinical content, a TF-IDF classifier 2 of 16; a single Apertus 8B answer without the checks catches 9 of 16

In progress

  • Review of the labels by a person; so far all labels come from the generating models
  • Full run on local weights without network
  • Handwritten and faxed test messages
  • Cost per 1,000 messages on GPU and CPU
